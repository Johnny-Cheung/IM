状态：已实施（2026-08-08）

关联设计：`消息链路改造设计.md` 第 9 节（"群聊 readAck 建议携带 lastReadGroupSeq，保存用户在该群的阅读游标"）。

## 1. 背景与目标

当前群聊未读的实现是**发送时计数**：

- 群消息发送 Lua 对除发送者外**每个成员**执行 `HINCRBY unread:{uid} convID 1`；
- 客户端打开会话发 `readAck` 后，服务端把该会话未读**整行清零**。

问题：

1. **语义粗糙**：清零是"整会话归零"，服务端不知道用户"读到第几条"；中途有新消息进来时，未读数无法精确表达"我上次看到哪"。
2. **写放大 O(成员数)**：每条群消息都要给每个成员写一次未读，是群消息发送 Lua O(N) 的组成部分。
3. **与设计文档规划不符**：`group_read_pos` 水位线接口在 repository 层已实现，但从未接入已读流程（半实现）。

目标：**群聊未读改为水位线模型** —— 未读 = 群最新 groupSeq − 我的已读游标，readAck 写游标而非清零，并顺带移除 Lua 中每成员的未读写。

## 2. 数据流对比

### 改前

```text
发送：Lua 写 outbox + 对每个成员 ZADD conv_order / HSET conv_meta / HINCRBY unread
已读：readAck {convId} → 清零 unread:{uid} 该会话行
读取：convSync 下发 unread:{uid} 全文（含群会话计数）
```

### 改后

```text
发送：Lua 写 outbox + 对每个成员 ZADD conv_order / HSET conv_meta（保留，见 §7）
     ← 移除 HINCRBY unread
已读：readAck {convId, lastReadGroupSeq} → HSet group_read_pos:{uid} convID = seq
读取：convSync 中群会话未读 = GET group_seq:{gid} − HGET group_read_pos:{uid}
     （私聊会话保持 unread hash 计数不变）
```

> 本次只移除未读的逐成员写；`conv_order/conv_meta` 的逐成员遍历保留（其读时合并为后续阶段，见 §7）。

## 3. 协议变更

`readAck` 增加**可选**字段：

```json
{ "type": "readAck", "data": { "convId": "g_5", "lastReadGroupSeq": 42 } }
```

兼容规则：

- 老客户端不带 `lastReadGroupSeq` → 服务端降级为"游标写到当前群最新 seq"（等价于现在的整会话清零，行为不变）。
- 私聊会话忽略该字段，保持现行为（清零 unread hash）。

## 5. 迁移方案

**一次性 Redis 脚本**（`redis-cli --eval`，发布前执行）：

```lua
-- 对每个群成员：read_pos = 当前群 seq − 该成员 hash 中的群未读数（clamp ≥ 0）
-- 例如按群扫描 group_members:{gid}，遍历成员：
--   local seq = tonumber(redis.call('GET', 'group_seq:' .. gid) or '0')
--   local unread = tonumber(redis.call('HGET', 'unread:' .. uid, 'g_' .. gid) or '0')
--   redis.call('HSET', 'group_read_pos:' .. uid, 'g_' .. gid, math.max(0, seq - unread))
```

**关键：执行顺序必须是"先迁移、后发布"**，数学上保证徽标连续：

```text
迁移时：read_pos_init = seq₁ − unread₁（旧代码下）
迁移后、发布前：旧 Lua 继续 HINCRBY，unread 增长 N 条
发布后：计算未读 = seq₂ − read_pos_init = (seq₁+N) − (seq₁−unread₁) = unread₁ + N = 当时的 hash 值 ✓
```

发布后读取路径自动忽略 hash 中群会话残留字段（按 §4 GetUnreadMap 改动），可选再清一轮。

## 6. 兼容性与回退

- **滚动部署**：字段可选 + 降级路径，新老客户端/服务器双向兼容；单实例部署无窗口问题。
- **回退**：git revert 恢复 HINCRBY + hash 读取即可；回退期间未读徽标短暂不准属可接受（无数据丢失），无需配置开关。
- **撤回不改变 groupSeq**（只改写内容），水位线天然兼容。

## 7. 本次不做（后续阶段）

1. **会话列表读时合并**：`conv_order/conv_meta` 移出 Lua，发送路径完全 O(1)（群消息发送不再遍历成员）；
2. **在线集合**：推送只扫在线成员（千人级群）；
3. **私聊逐条已读**：readAck 用字符串手术更新收件箱消息 `readStatus`。

## 8. 测试与回归

- 单元（service）：群 readAck 写游标 / 字段缺省降级 / 私聊清零不受影响；
- 单元（repo）：`GetUnreadMap` 游标差计算、clamp、缺游标防御、群字段忽略；
- Lua：群消息发送后 `unread:{uid}` 不再增长（`lua_message_write_test`）；
- 集成（真实 Redis）：迁移脚本幂等 + 徽标连续；
- E2E：三人群，A 发 2 条 → B 打开会话 → 未读按游标语义精确（读到 1 条则剩 1）；
- 回归：私聊未读全流程、`问题反馈记录.md` 新增本次回归记录。

## 9. 验收标准

1. 群未读 = 游标差，readAck 带 seq 后"我上次看到第 N 条"语义正确；
2. 群消息发送 Lua 每成员写从 3 次降到 2 次；
3. 迁移前后所有成员未读徽标数字不变（抽样验证）；
4. 老客户端（不带新字段）行为与改造前一致。
