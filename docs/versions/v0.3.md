# v0.3 好友体系

状态：范围已对齐，待实现。

## 目标

在 v0.2 用户体系之上加入好友功能：按用户名精确查找用户，发送、接受、拒绝好友申请，查看好友列表并删除好友。本版本仍然不做聊天和 WebSocket。

## 已确认范围

### 页面

- 新增独立的 `/friends` 好友管理页。
- 登录后的主页保留 v0.2 占位内容，增加“好友管理”入口。
- `/friends` 页面包含：添加好友、好友申请、我的好友三个区域。
- 桌面和手机浏览器均可使用；删除好友需要二次确认。
- 页面进入时加载；标签页重新可见或窗口重新聚焦时刷新；提供手动“刷新”按钮，不做定时轮询。
- 页面外不显示好友申请未读提示，留到后续实时/未读能力统一处理。

### 查找用户

- 只支持按完整用户名精确查找，不区分大小写，不支持模糊搜索或用户列表。
- 查询结果展示昵称和 `@用户名`，以及当前关系状态。
- 关系状态：`self`（自己）、`friend`（已是好友）、`incoming_pending`（对方已申请）、`outgoing_pending`（你已申请）、`none`（无关系）。
- 未找到用户时展示明确提示，不暴露其他用户数据。
- 不能向自己发送好友申请。

### 好友申请

- 申请接口需要登录；同一对用户同一方向只保留一条待处理申请。
- 用户可以向非好友、无待处理申请的用户发送申请。
- 已是好友、已有待处理申请或向自己申请时，服务端拒绝并返回明确错误。
- 双方互相发送申请时自动建立好友关系，并删除两条待处理申请。
- 收到申请的人可以接受或拒绝；其他人不能处理。
- 接受后建立双向好友关系；拒绝只删除当前申请。
- 拒绝后允许立即重新申请，不设置冷却时间。
- 本版本不提供申请附言、撤回已发出的申请或拉黑。

### 好友列表与删除

- 好友列表展示昵称和 `@用户名`，按昵称、用户名排序。
- 删除好友会同时删除双方的好友关系；删除后双方可以重新申请。
- 删除不存在的好友关系返回明确错误。
- 好友关系删除不影响未来的聊天历史；本版本尚无消息数据。

## 数据模型

新增两张表，迁移编号从 `003` 开始，现有用户和会话数据保留。

### friend_requests

- `id`：内部自增主键。
- `from_user_id`、`to_user_id`：申请双方，关联 `users.id`。
- `created_at`：申请时间，UTC。
- 唯一键 `(from_user_id, to_user_id)`；同一方向只能有一条待处理申请。
- 反向申请允许存在，由业务逻辑自动转为好友关系。
- 禁止自己申请自己。

### friendships

- `user_id`、`friend_user_id`：好友关系双方，关联 `users.id`。
- `created_at`：建立时间，UTC。
- 主键 `(user_id, friend_user_id)`。
- 一条好友关系保存两行（A→B 和 B→A），便于双方列表查询和删除。
- 禁止自己成为自己的好友。

## 接口

所有接口都需要登录，错误格式沿用 `{"error":{"code":"...","message":"..."}}`。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/users/{username}` | 按用户名精确查找，返回昵称和关系状态 |
| `POST` | `/api/friend-requests` | 发送申请；双方互相申请时直接建立好友关系 |
| `GET` | `/api/friend-requests` | 返回收到和发出的待处理申请 |
| `POST` | `/api/friend-requests/{id}/accept` | 接受申请 |
| `POST` | `/api/friend-requests/{id}/reject` | 拒绝申请 |
| `GET` | `/api/friends` | 好友列表 |
| `DELETE` | `/api/friends/{username}` | 删除好友 |

主要错误码：

- `unauthenticated`：未登录或会话失效。
- `user_not_found`：查找的用户不存在。
- `cannot_add_self`：不能添加自己。
- `already_friends`：已经是好友。
- `request_exists`：已有待处理申请。
- `request_not_found`：申请不存在、已处理或不属于当前用户。
- `friend_not_found`：好友关系不存在。

2. 增加用户查找和好友接口，补 handler 测试，开发机 canary 验证数据与权限。

## 本版本不做

- 聊天、消息、WebSocket。
- 模糊搜索、用户推荐和通讯录导入。
- 拉黑、举报、好友备注和分组。
- 好友申请附言和撤回已发申请。
- 页面外的申请未读徽标和实时推送。
- 多端同时登录。

## 验收方向

1. 可以按用户名精确找到用户，并正确显示自己、好友、收到申请、已发出申请和无关系状态。
2. 好友申请可以发送、接受和拒绝；重复申请、加自己、加好友会被拦截。
3. 双方互相申请时自动成为好友。
4. 好友列表正确；删除好友后双方关系消失，可以重新申请。
5. `/friends` 页面在进入、重新聚焦和手动刷新时更新；桌面和手机宽度可用。
6. 未登录访问好友接口返回 401；测试数据清理后数据库保持一致，旧 `/opt/IM` 不受影响。
