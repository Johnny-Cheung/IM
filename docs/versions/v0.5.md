# v0.5 消息体验补全

状态：已验收（与 v0.4 联合验收）。

## 目标

在 v0.4 文本私聊之上补齐未读、已读、自动重连和单聊天连接策略，让消息在刷新、断线和多窗口场景下保持一致。

## 已确认范围

### 未读

- 会话列表展示每个会话的未读消息数量；未读只统计对方发给当前用户、且尚未读到的消息。
- 没有未读时不显示数量；进入会话或当前会话在前台停留时，已有消息和后续新消息自动已读。
- 页面在后台时不自动已读；回到前台后，如果当前会话仍打开，再统一标记为已读。
- 未读数量和已读位置保存在服务端，刷新页面、重新登录或换设备后保持。
- 自己发出的消息不产生未读数量。

### 已读

- 服务端保存每个用户在每个会话中的最后已读消息 ID。
- 发送方只在最后一条自己发出的消息下显示“已读/未读”；不为每条消息单独显示回执。
- 接收方标记已读后，通过 WebSocket 实时通知发送方；断线重连或刷新后通过会话列表恢复。
- 删除好友后，历史会话仍可查看；查看时也按相同规则标记已读。

### 断线重连

- WebSocket 因网络异常断开后自动退避重连，重试间隔逐次增加，达到上限后保留手动“重新连接”按钮。
- 重连成功后：
  - 刷新会话列表，更新未读数量和对方已读位置。
  - 当前打开的会话自动补收断线期间遗漏的消息。
- 页面重新可见或网络恢复时，如果实时连接未建立，会主动重连。
- 单次重连最多自动补收 500 条消息；超过时回退加载最新一页，用户可继续向上翻页。
- 主动退出、账号会话失效、被其他窗口接管时不做自动重连。

### 单聊天连接

- 同一账号只保留一个在线聊天 WebSocket 连接。
- 在其他窗口或标签页打开聊天工作区时，新连接替换旧连接。
- 旧窗口显示“聊天已在其他窗口打开”，禁止发送新消息，但保留历史查看。
- 旧窗口提供“重新登录”按钮，跳转到登录页，不提供“在此窗口继续”或自动抢回连接的按钮。
- 旧窗口的“重新登录”不会立即结束其他窗口的会话；如果在该登录页重新提交登录，会按单会话规则替换账号会话，原窗口随后退出登录。
- 被替换的旧窗口不参与已读标记，也不自动重连。

### 会话连接状态

- 页面显示实时连接状态：连接中、实时在线、实时断开、已被接管。
- 手动退出、修改密码、账号在新设备登录时，旧聊天连接关闭并跳转登录页。

## 数据模型

新增 `conversation_reads` 表，迁移编号从 `010` 开始。

- `user_id`：读取方，关联 `users.id`。
- `peer_user_id`：会话对方，关联 `users.id`。
- `last_read_message_id`：读取方在该会话中最后读到的消息 ID；从未读取时为 0 或不建行。
- `updated_at`：最后更新时间，UTC。
- 主键 `(user_id, peer_user_id)`；禁止自己作为自己的会话对方。
- 不新增消息表字段；未读数量由消息记录和已读位置计算。

会话接口增加：

- `unread_count`：当前用户在该会话的未读数量。
- `peer_last_read_message_id`：对方在該会话的最后已读消息 ID，用于发送方展示“已读/未读”。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/conversations/{username}/read` | 标记当前用户在该会话的收到消息为已读 |
| `GET` | `/api/conversations/{username}/messages?after_id=` | 断线重连后按消息 ID 补收遗漏消息，与 `before_id` 互斥 |

已有会话列表和历史接口增加未读、已读字段；标记已读返回更新后的 `last_read_message_id`。

WebSocket 增加 `messages.read` 事件：

- `reader`：标记已读的用户名。
- `peer`：会话对方用户名。
- `last_read_message_id`：更新后的最后已读消息 ID。

连接关闭码：

- `4001`：聊天连接被新窗口接管，客户端显示只读提示且不自动重连。
- `4002`：账号会话被替换、退出或密码修改，客户端跳转登录页并显示对应提示。

## 本版本不做

- 逐条消息已读回执、已读回执列表和已读时间线。
- 消息撤回、删除、搜索、转发。
- 图片、文件、语音、视频和群聊。
- 输入中状态、在线状态、系统推送和消息免打扰。
- 多端同时在线和多设备消息同步。
- 未读数量的页面图标或浏览器通知。

## 验收方向

1. 对方发消息而当前会话未打开或页面在后台时，会话列表未读数量增加；自己发出的消息不增加未读。
2. 打开会话或回到前台后未读清零，发送方在最后一条自己消息下看到“已读”。
3. 刷新、重新打开页面后未读数量和已读状态保持正确。
4. 网络断开后页面自动重连；重连成功后当前会话补齐断线期间消息，会话列表同步未读和已读。
5. 同一账号第二个聊天窗口打开后，新窗口实时在线；旧窗口显示“聊天已在其他窗口打开”，不能发送但可查看历史，并提供“重新登录”。
6. 旧窗口点击“重新登录”进入登录页；重新登录会按单会话规则替换账号会话。
7. 退出登录、修改密码、账号被新会话替换时，旧连接关闭并跳转登录页。
8. 桌面和手机布局正常，无横向溢出；测试数据清理后现有账号、好友关系和消息不受影响。
