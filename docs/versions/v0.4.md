# v0.4 文本私聊

状态：部署验证通过；用户决定与 v0.5 一起验收。

## 目标

在好友体系之上加入一对一文字聊天：登录后的主页成为聊天工作区，会话列表展示所有好友，消息保存在服务端，通过 HTTP 发送、WebSocket 实时接收，历史消息滚动加载。

## 已确认范围

### 页面

- 登录后的主页 `/` 即聊天工作区，不再保留 v0.2/v0.3 的占位主页。
- 桌面布局为左侧会话列表、右侧当前对话；手机布局在会话列表和对话之间切换。
- 会话列表展示所有好友，包括还没有任何消息的好友。
- 有消息的会话按最后一条消息时间倒序排列；没有消息的好友排在后面，按昵称、用户名排序。
- 好友页每个好友增加“发消息”入口。
- 当前会话使用 `/chat/{username}`，刷新页面后仍然打开同一个会话；它属于聊天工作区，不是独立的聊天页面。
- 删除好友后，已有会话和历史保留在会话列表中，但变为只读，输入框禁用；仍可查看历史。

### 消息

- 只有好友之间可以发送新消息；非好友发送返回明确错误。
- 支持文字、换行和表情字符；单条消息去除首尾空白后为 1–2000 个字符，纯空白拒绝。
- 消息正文按纯文本保存和展示，不解析 Markdown 或 HTML。
- 服务端为消息分配自增 ID 和创建时间；界面按 ID 正序展示。
- 发送消息使用 HTTP 请求；服务端保存成功并返回消息后视为已发送。
- 发送中显示“发送中”；失败显示“发送失败”并允许重试。
- 客户端为每条消息生成 `client_message_id`；同一发送者重复提交同一 ID 时只保存一条，重试返回已保存的消息。
- 接收新消息通过 WebSocket 推送；发送者自己的其他标签页也可以收到同一条消息。
- 对方离线时消息不丢失，下次打开会话或刷新时通过历史接口获取。
- 历史消息按页加载，默认每页 30 条；滚动到顶部附近时自动加载更早消息，并保持当前滚动位置。
- v0.4 不做未读、已读、撤回、删除、搜索、转发、图片、文件、群聊、输入中状态和在线状态。

### 连接

- WebSocket 使用现有登录会话鉴权，只接收当前用户相关的新消息。
- WebSocket 断开时页面显示“实时连接已断开”，提供手动“重新连接”；自动重连、单聊天连接和更完整的断线策略留到 v0.5。
- 手动重连会恢复实时连接并刷新会话列表；断线期间当前会话遗漏的消息，需要重新打开会话或刷新页面获取，自动补收留到 v0.5。
- v0.4 允许同一账号多个标签页同时接收消息；同一账号只保留一个聊天连接的策略在 v0.5 讨论。

## 数据模型

新增 `messages` 表，迁移编号从 `009` 开始。

- `id`：内部自增主键，同时作为消息排序和分页游标。
- `sender_id`、`recipient_id`：发送者和接收者，关联 `users.id`。
- `client_message_id`：客户端生成的幂等 ID，例如 UUID。
- `body`：消息正文。
- `created_at`：服务端接收时间，UTC。
- 唯一键 `(sender_id, client_message_id)`；同一发送者同一客户端 ID 只保存一条。
- 索引支持按双方查询历史，以及查询每个会话的最后一条消息。
- 禁止给自己发送消息。
- 不新增会话表，会话列表由好友关系和消息记录合并得出。

## 接口

所有 HTTP 接口都需要登录，错误格式沿用 `{"error":{"code":"...","message":"..."}}`。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/conversations` | 返回所有好友会话及已有消息的非好友会话，含最后一条消息 |
| `GET` | `/api/conversations/{username}/messages` | 按 `before_id` 游标分页返回双方历史消息 |
| `POST` | `/api/conversations/{username}/messages` | 保存并发送消息；重复 `client_message_id` 返回已有消息 |
| `GET` | `/api/ws` | WebSocket 连接，推送新消息 |

消息对象包含 `id`、`sender`、`recipient`、`body`、`created_at` 和 `client_message_id`。

会话对象包含对方用户、是否为好友、最后一条消息及时间；没有消息时为 `null`。

主要错误码：

- `unauthenticated`：未登录或会话失效。
- `user_not_found`：目标用户不存在。
- `not_friends`：双方已不是好友，不能发送新消息。
- `invalid_message`：消息为空或请求格式不正确。
- `message_too_long`：消息超过 2000 个字符。
- `invalid_client_message_id`：客户端消息 ID 格式不正确。

WebSocket 事件：

- `message.created`：服务端保存新消息后推送给发送者和接收者，包含完整消息对象。
- 连接建立后不补发历史；历史统一通过 HTTP 分页接口获取。

## 本版本不做

- 未读、已读和已读回执。
- 自动重连、单聊天连接替换和多端登录策略。
- 撤回、删除、搜索、转发和消息重发历史。
- 图片、文件、语音、视频和群聊。
- 输入中状态、在线状态和系统通知。
- 拉黑、举报和消息举报。

## 验收方向

1. 登录后主页显示会话列表和聊天工作区；所有好友都在列表中，没有消息的好友也能直接开始聊天。
2. 两个好友能通过 HTTP 发送消息，并通过 WebSocket 实时收到；发送中、发送成功和失败重试状态正确。
3. 同一 `client_message_id` 重复提交只保存一条消息，界面不出现重复消息。
4. 打开会话加载最近 30 条，滚动到顶部会自动加载更早消息，顺序和滚动位置正确。
5. 非好友不能发送新消息；未登录不能读取或发送；用户只能读取自己参与的会话。
6. 删除好友后双方不能继续发送，但会话历史仍可查看且为只读。
7. 刷新页面后会话和当前聊天恢复；WebSocket 断开时有明确提示和手动重连；断线期间的消息通过重新打开会话或刷新获取。
8. 桌面和手机浏览器均可正常使用，无横向溢出；测试数据清理后现有账号和好友关系不受影响。
