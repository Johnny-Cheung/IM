# v0.2 用户体系

状态：实现方案已对齐，待实现。

## 目标

建立基础用户体系，让用户可以通过浏览器注册、登录、退出，并管理自己的昵称和密码。登录状态使用服务端会话保存；本版本暂不实现好友、消息或其他 IM 业务功能。

## 已确认范围

### 账号

- 注册必填：用户名、昵称、密码。
- 用户名是登录名，也是对外用户 ID；不再额外生成随机用户 ID。
- 用户名长度 3–20 位，仅允许英文字母、数字和下划线。
- 用户名不区分大小写且全局唯一，注册后不可修改。
- 昵称长度 1–20 个字符，可以重复，可以在登录后修改。
- 昵称允许中文、英文、数字、表情和空格，但去除首尾空白后不能为空；本版本不做头像。
- 密码至少 8 个 Unicode 字符，UTF-8 编码最多 72 字节；注册和修改密码都需要确认密码。
- 本版本暂不做邮箱、手机号、验证码、找回密码或第三方登录。

### 登录与会话

- 登录只使用用户名和密码。
- 注册成功后直接建立登录会话。
- 一个账号同一时间只保留一个有效登录会话。
- 新设备登录成功后，旧设备的会话立即在服务端失效；旧设备下一次请求受保护接口时返回登录失效，并明确提示账号已在其他设备登录。
- 退出只撤销当前会话。
- 会话从登录时开始固定有效 7 天，不因请求自动续期。
- 修改密码成功后撤销全部会话，当前设备也回到登录页。
- 登录态使用 HttpOnly Cookie 携带随机会话标识，具体 Cookie 安全属性在实现前确定。

### 页面

- 未登录用户进入受保护页面时回到登录页。
- 提供登录页和注册页。
- 登录后进入简单的空白主页，只展示登录成功、当前会话状态和退出入口。
- 提供独立的账号设置页：用户名只读展示，可修改昵称和密码。
- 不在本版本加入好友、聊天、WebSocket 或消息页面。
- 页面同时适配桌面浏览器和手机浏览器。

### 数据存储与部署

- MySQL 8.4 运行在独立容器中，使用 `/opt/IM-Rebuild` 下的第二套 Docker 运行时（独立 socket、数据目录和镜像目录），不复用旧 `/opt/IM` 的 Docker 守护进程。
- 容器数据目录为 `/opt/IM-Rebuild/mysql/data`，只监听 `127.0.0.1:13306`；配置和凭据文件权限为 0600。
- 本地开发通过仓库根目录的 Compose 文件启动 MySQL 8.4，不依赖开发机。
- 用户表使用内部 `BIGINT UNSIGNED AUTO_INCREMENT` 主键；用户名同时作为登录名和对外唯一标识，不生成额外随机 ID。
- 会话由服务端持久化保存，并与用户内部主键关联；同一账号只保留一个有效会话，旧会话保留撤销记录以区分下线原因。
- 后端启动时自动执行数据库迁移，使用 `schema_migrations` 表记录版本。

## 本版本不做

- 好友申请、好友管理和用户查找页面。
- 私聊、群聊、WebSocket 和消息存储。
- 头像、邮箱、手机号、验证码、密码找回和第三方登录。
- 多端同时登录、设备管理和登录设备列表。
- 管理后台和人工审核注册。

## 已确定的实现方式

### 后端

- 继续 Go + Gin，新增 MySQL 驱动和 bcrypt。
- 代码分为 `internal/config`、`internal/store`、`internal/auth`、`internal/httpapi`；`cmd/server` 负责组装和启动。
- 用户名保存原始大小写，另存小写唯一键；登录不区分大小写。
- 密码使用 bcrypt cost 10；登录失败也执行一次假哈希，避免通过响应时间判断用户名是否存在。
- 会话 token 为 32 字节安全随机数，Cookie 保存原文，数据库保存 SHA-256。
- Cookie 为 `im_session`，`HttpOnly`、`SameSite=Lax`、`Path=/`、有效期 7 天；开发机 HTTP 暂不启用 `Secure`。
- 登录时在事务内撤销该用户当前有效会话并创建新会话；退出、改密分别记录撤销原因。
- 接口：`POST /api/auth/register`、`POST /api/auth/login`、`POST /api/auth/logout`、`GET /api/me`、`PATCH /api/me`、`PUT /api/me/password`。
- 错误统一为 `{"error":{"code":"...","message":"..."}}`。
- `/health` 保持进程存活检查；新增 `/ready` 检查 MySQL。
- 静态托管增加 SPA fallback：非 `/api`、非静态资源的 GET/HEAD 返回 `index.html`。
- v0.2 不做登录限流、CSRF token 和 HTTPS，作为当前限制记录，后续版本补充。

### 前端

- 引入 `react-router-dom`，使用 Browser 路由：`/login`、`/register`、`/`、`/settings`。
- 未登录访问受保护页面跳转登录页；401 按错误码显示账号被其他设备登录、登录过期或改密失效。
- 登录后主页只显示登录成功、当前会话状态、账号设置入口和退出。
- 账号设置页展示只读用户名，支持修改昵称和密码。
- 使用轻量 AuthContext + fetch，不引入状态管理库。

### 本地与开发机

- 仓库根目录提供 Compose 文件，仅启动 MySQL 8.4；后端通过 `IM_MYSQL_DSN` 环境变量连接。
- 开发机使用独立 Docker 运行时和 MySQL 容器，`imctl` 负责先等 MySQL 就绪再启动后端。
- MySQL 容器限制 512 MB 内存、0.5 CPU；后端限制 128 MB 内存、25% CPU。

## 实现步骤

1. 后端接入 MySQL：配置、迁移、连接池、`/ready`，并补基础测试。
2. 实现注册、登录、退出和单会话中间件；补接口测试。
3. 实现昵称修改和密码修改，验证撤销会话。
4. 前端接入路由和登录态，完成登录页、注册页和空白主页。
5. 完成账号设置页和各类 401 提示。
6. 本地联调、浏览器验收并更新文档。
7. 开发机部署独立 Docker 与 MySQL，完成部署验收。

## 当前限制

- 开放注册且 v0.2 不做登录限流；当前只适合内网小范围使用。
- 开发机使用 HTTP，Cookie 暂未启用 `Secure`，也没有 CSRF token。
- 不做已撤销或过期会话记录的定时清理。
- 不做头像、好友、聊天、多端登录和密码找回。

## 验收方向

1. 新用户可以注册，重复用户名不能注册，注册成功后直接进入登录态。
2. 登录、退出、刷新页面和 7 天会话有效期行为符合约定。
3. 同一账号在新设备登录后，旧设备下一次访问受保护接口会被明确要求重新登录。
4. 登录后可以进入账号设置，修改昵称和密码；修改密码后当前会话失效。
5. 未登录访问受保护页面或接口会被拦截，登录页和注册页在桌面、手机宽度下可用。
6. MySQL 数据持久化有效，重启后用户和会话数据按约定处理；新部署不影响旧 `/opt/IM` 服务。
