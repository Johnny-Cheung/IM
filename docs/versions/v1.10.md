# v1.10 删除私聊 feed，直聊/群聊改为按会话懒加载

状态：开发中（2026-11-02）。本版删除 `dm:feed`/`index:epoch`，把私聊同步从“按用户全量增量”改为“会话列表元数据 + 打开会话时按 `seq` 懒加载”；群聊的 bootstrap 增量也一并移除。开发阶段在 8199 验证，不切换正式 8198。

## 目标

去掉 v1.4 引入、只为全局私聊增量服务的 `dm:feed:{user}` 和 `index:epoch`，让直聊与群聊使用同一套读取模型：

- 消息只保留在 `messages:{id}`/`group-messages:{id}` 实体、私聊会话索引 `dm:pair`、群信箱 `group:{G}:inbox`；
- 会话列表只读 `dm:conv-last`、`dm:seq`、`dm:read` 和 MySQL 的会话/群成员信息；
- 用户上线只拿会话列表元数据（`last_seq`、`last_message`、`unread_count`），打开哪个会话才加载哪个会话的消息；
- 不改 MySQL 表结构、不做数据迁移、不新增 Redis 键、不改发送/已读/群聊/朋友圈语义、不改 `bench/`。

## 背景

v1.4 为实现“跨会话增量同步”新增了 `dm:feed:{user}`：每条私聊消息在收发双方的 feed 各写一次，分数为全局消息号；`GET /api/messages/sync?after_id=N` 和 `POST /api/bootstrap` 的 `direct` 增量都从它读取。`index:epoch` 只用于标记 feed 的全局消息号完整边界。

这条索引和现有读取模型重复：

- `dm:pair:{low}:{high}` 已经按会话 `seq` 保存了全部私聊消息；
- `dm:conv-last:{user}` 已经保存每个会话最后一条消息；
- `dm:seq`/`dm:read` 已经提供会话计数器和未读；
- 群聊从 v1.3 起就是 `group:{G}:inbox` + 每群 `seq`，没有按成员展开的 feed。

继续保留 feed 的代价是每条私聊多两次 `ZADD`、每用户一条不设 TTL 的 ZSET、`index:epoch`/feed 重建校验/feed 深度对账和 `feed_repairs` 指标；而前端每个会话只缓存 200 条，冷启动拉全部历史大部分会被淘汰。

## 已确认决策

1. **删除 `dm:feed:{user}` 和 `index:epoch`。** 新代码不再写入、读取或创建这两个键。
2. **删除 `GET /api/messages/sync`。** 项目从 v1.8 起不做向后兼容；旧客户端不保留。
3. **bootstrap 只返回元数据。** `POST /api/bootstrap` 返回 `user`、完整 `conversations`、`friends` 和 `partial`；不再返回 `direct`/`groups`，不再接收 `after_id`/群游标。
4. **直聊和群聊都懒加载。** 打开会话时用本地 `localSeq` 与列表 `last_seq` 比较，落后就按 `after_seq` 补齐；没有缓存或跨度过大时取最新一页。
5. **保留会话级完整性机制。** 继续使用 `dm:pair` 缺口检查、`dm:conv-last` 预览审计、实体/计数器/水位对账和 `rebuild-redis`；只移除 feed 专属部分。
6. **旧键一次性清理。** 升级后按精确前缀 `SCAN` + `UNLINK` 删除 `dm:feed:*`，再删除 `index:epoch`；`rebuild-redis` 的 `dm:*` 清理模式也会删 feed，epoch 需显式删除。绝不 `FLUSHDB`/`FLUSHALL`。
7. **不改 MySQL 表结构。** `messages`、`group_messages`、`conversation_reads`、`group_members` 等保持现状。
8. **开发阶段不切 8198。** 只在 8199/`im:v13-verify` 验证；8198/`im:v12` 和共享容器不动。

## 保留与删除的 Redis 数据

键名省略命名空间前缀（正式 `im:v12:`，验证 `im:v13-verify:`）。

| Redis 结构 | 去留 | 作用 |
| --- | --- | --- |
| `messages:{id}` | 留 | 私聊消息实体 |
| `group-messages:{id}` | 留 | 群消息实体 |
| `dm:pair:{low}:{high}` | 留 | 私聊会话内索引，分数为会话 `seq` |
| `dm:seq:{low}:{high}` | 留 | 私聊会话计数器 |
| `dm:conv-last:{user}` | 留 | 会话列表最后一条消息 ID |
| `dm:read:{user}` | 留 | 私聊已读水位 |
| `group:{G}:inbox` / `group:{G}:seq` / `group:{G}:read` | 留 | 群消息索引、计数器和已读 |
| `friends`、群成员/解散投影、`dedup`、消息/已读 Stream、`seq:ready`、`messages:next_id` | 留 | 现有链路 |
| `dm:feed:{user}` | **删** | 唯一用途是整用户私聊增量 |
| `index:epoch` | **删** | 只为 feed 判断全局消息号完整边界 |

## API 契约

### bootstrap

```http
POST /api/bootstrap
Content-Type: application/json

{}
```

```json
{
  "user": { "username": "...", "nickname": "..." },
  "conversations": [],
  "friends": [],
  "partial": ["conversations"]
}
```

- `conversations` 是完整列表，包含私聊和群聊，字段沿用现有 `last_seq`、`last_message`、`unread_count`、`peer_last_read_seq`。
- 不再有 `direct`、`groups`、`after_id`、`groups[].after_seq`、`limit`。
- `partial` 只可能包含 `conversations`、`friends`；对应部分失败时客户端保留本地缓存。
- 列表不分页，因为 `writeConversations` 会把不在列表中的会话缓存删除。

### 已删除

- `GET /api/messages/sync?after_id=N` 不再注册，返回 404。
- `ReadFeed`/`FeedPage`/`feedEpoch`/`EnsureIndexEpoch` 删除。

### 会话历史

沿用现有接口：

- `GET /api/conversations/{username}/messages?before_seq=N&limit=30`：向前翻页；
- `GET /api/conversations/{username}/messages?after_seq=N&limit=50`：补齐缺口；
- 群聊对应 `/api/groups/{id}/messages`；
- 读取只依赖 `dm:pair`/`group:{G}:inbox`、会话计数器、消息实体和 MySQL 回落，不读 feed/epoch。

## 客户端缓存与懒加载

`SyncState` 从 `{afterID, directComplete, groups, localSeq, savedAt}` 收敛为 `{localSeq, savedAt}`：

- `localSeq` 是每个会话（`direct:{username}`/`group:{id}`）本地已知的最大 `seq`，继续由 `writeMessages`/`deleteMessagesFrom` 维护；
- 旧 IndexedDB 记录里的 `afterID`/`directComplete`/`groups` 被宽容忽略，仍保留 `localSeq`；不提升 DB 版本，不清空已缓存消息；
- 缓存上限仍是每会话 200 条、全账号 10000 条、100 个会话；`enforceUserLimits` 从“仅 bootstrap 调用”扩展到懒加载写入后的 debounce 调用。

打开会话的流程：

1. 先渲染本地缓存；
2. 用 `localSeq`/缓存最大 `seq` 与列表 `last_seq` 比较；
3. 没有缓存或 `localMax===0`：取最新一页；
4. `last_seq > localMax`：从 `localMax` 开始 `after_seq` 补齐，最多 500 条；超过则取最新一页；
5. 之后对缓存范围做一次空洞检查，缺失的 `seq` 用 `pullGaps` 补；无洞时不发请求；
6. 重连/切回前台对当前会话重复 3–5 步；切换会话时旧请求按 target/version 丢弃。

离线模式只能查看已经打开过并写入缓存的会话；从未打开过的会话没有正文，会提示“当前离线，这个会话没有缓存”。列表预览和未读数仍然可用。

## 一致性与降级

- 私聊历史优先读 `dm:pair` + `messages:{id}`；实体或索引缺失时按 `seq` 回落 MySQL 并由读取路径合并。
- 群聊历史优先读 `group:{G}:inbox` + `group-messages:{id}`；缺失时回落 MySQL。
- 会话列表：MySQL 提供会话/好友基础信息，Redis 提供 `last_seq`、`last_message`、未读和对方已读；Redis 不可用时按现有本地模式用 MySQL 计算。
- 不再有“feed 不完整 → 整个私聊缓存不可信”的全局标记；每个会话用自己的 `localSeq`/`last_seq`/空洞检查判断。
- 已读：`focus` 仍表示打开会话推进到最新；停留前台时客户端 `read` 游标按渲染位置推进，服务端只做 clamp/max；发送者自读仍由 `implicitRead` 异步推进。

## 重建、对账与 backfill

### rebuild-redis

- 消息主遍不再写 `dm:feed`，也不再校验每用户 feed 基数。
- 不再设置/撤回 `index:epoch`；校验通过后只写 `seq:ready`。
- `ClearNamespace` 保留 `dm:*` 清理模式（会清掉旧的 `dm:feed:*`），并显式删除 legacy `prefix + "index:epoch"`。
- 保留 `dm:pair`、`dm:seq`、`dm:conv-last`、`dm:read`、群投影、去重、消息实体、Stream、`messages:next_id` 和 `seq:ready` 的写入/校验。

### 对账

- 删除每小时 feed 抽样、feed 缺口修复、feed 游标和 `feed_repairs` 指标。
- **保留 `auditUserConversationLast`**：按 `ListUserIDs` 轮转用户，审计并修复 `dm:conv-last` 预览和缺失实体；用户的 deferred retry 逻辑保留。
- 保留每 5 分钟的 `dm:pair`/群 inbox 缺口、计数器、已读水位检查，以及实体抽样审计。
- `/ops/infra` 的 `pipeline.reconcile` 不再包含 `feed_repairs`；`redis_missing`、`redis_repaired`、`watermarks_raised`、`needs_rebuild`、`last_deep_audit_at`、`deep_audit_error` 保留。

### backfill-seq

`index:epoch` 删除后，`projectionMarkerKeys` 只检查 `messages:next_id`：MySQL 有条目而全局计数器缺失，视为投影整体丢失，拒绝 backfill；空数据库仍是合法的首次 backfill。部分丢失仍由对账处理。

## 旧键清理与回滚

升级后新代码不再读写 `dm:feed:*` 和 `index:epoch`，但旧键不会自动消失：

```text
# 仅验证命名空间；正式切换时再把 im:v13-verify 换成 im:v12
SCAN <cursor> MATCH im:v13-verify:dm:feed:* COUNT 100
UNLINK <返回的键>
DEL im:v13-verify:index:epoch
```

- 不使用 `FLUSHDB`/`FLUSHALL`，不删除未知键。
- `rebuild-redis` 的 `dm:*` 模式会清理 `dm:feed:*`；`ClearNamespace` 会显式删除 legacy `index:epoch`。
- 正式 8198/`im:v12` 本轮不操作；切换时按同一流程执行。
- 回滚到 v1.9 或更早版本需要用旧二进制重新执行 `rebuild-redis` 生成 `dm:feed`/`index:epoch`，否则旧 `/api/messages/sync` 会返回空/不完整结果。v1.7 回滚还需要旧的命名空间清理和 backfill 流程。Redis 不在备份范围，MySQL 仍是权威。

## 风险与取舍

- **未打开会话/群不再预缓存正文。** 登录只保证列表预览和未读数；离线只能看访问过的会话。这是本版明确接受的行为变化。
- **全局完整性标记消失。** 用每会话 `localSeq`、`last_seq`、打开时补洞和 `pullGaps` 替代；需要测试覆盖离线多会话、中间空洞、seq 复用/resync。
- **首开与 socket 同步可能重复请求。** 用 target 级“初始加载进行中”标记协调 `loadInitialMessages` 和 `syncActiveMessages`；不再沿用“bootstrap 已预取所以跳过首次同步”。
- **缓存上限需要主动维护。** `enforceUserLimits` 必须在懒加载/WS 写入后 debounce 调用，否则 10k/100 限制失效。
- **bootstrap 列表必须完整。** `writeConversations` 会删除不在列表中的会话缓存；列表不分页，`partial` 时客户端不覆盖。
- **旧键清理和回滚。** `index:epoch` 不被 `dm:*` 匹配，必须显式清理；旧版本回滚前必须 rebuild 生成 feed/epoch。
- **对账覆盖变化。** feed 抽样消失；`dm:pair` 缺口、`dm:conv-last` 预览、实体、计数器和水位审计保留。
- **容量结论待重测。** 删除 2 次 `ZADD`/条和 feed 内存可能改变 Redis 上限，但本轮不把旧压测数字当结论，也不修改 `bench/`。
