# v1.8.1 会话消息号与会话内水位

状态：方案已确认（2026-10-28），待开发。属于 [v1.8 可靠性与一致性](v1.8.md)。

## 目标

给每个会话（一对好友的私聊、一个群）增加会话内连续递增的消息号，并以它为基础简化读模型：

- 未读数用两个数相减得到，不再对消息索引做 `ZCOUNT`；
- 私聊的两个方向合并成一个会话索引，历史分页只读一个 key；
- 客户端能通过编号发现丢失的消息和服务端回退；
- 为 v1.8 后续的对账和跨实例广播自愈提供依据：会话内消息条数应等于最大编号。

## 背景

- 当前全局消息号（Redis `INCR`，私聊和群聊共用）全局唯一，但在单个会话内不连续。客户端收到 120 号，无法判断 101 到 119 里有没有这个会话的消息，只能靠断线重连后按游标补拉兜底。
- 私聊未读是对 `dm:conv:{我}:{对方}` 做 `ZCOUNT`。该 key 按方向拆分，只含对方发给我的消息，一对好友有两个；会话历史要合并两个 key 再排序。
- 群聊未读是对 `group:{G}:inbox` 做 `ZCOUNT`。
- `ZCOUNT` 是 O(log N)，速度不是主要问题。主要收益是丢消息检测、对账和读路径简化。

## 已确认决策

1. **新增会话消息号 `seq`。** 每个会话从 1 开始，每接纳一条消息加 1，会话内单调连续、无空洞。它只在会话内唯一；全局唯一仍由现有全局消息号负责，（会话，`seq`）合起来全局唯一。
2. **全局消息号保留。** 继续用于 feed 增量同步、消息实体键、MySQL 主身份和跨会话唯一标识。
3. **会话的定义。** 私聊以“一对用户”为一个会话，由两人的内部用户 ID 确定（小的在前）。删除好友再加回来，编号接着往下排，历史不断。群以群为一个会话。
4. **用 Redis 原子自增分配。** 在接纳 Lua 里，非好友、非成员、重复、正文冲突等拒绝判断全部完成之后，才对会话计数器加 1，与写入消息、索引、幂等记录在同一次原子执行内。重复发送命中幂等时返回原编号，不再分配。
5. **私聊 `dm:conv` 二合一。** 一对好友一个会话索引，双方消息都进去，分数为 `seq`，成员为全局消息号，消息实体键不变。`dm:conv-last` 保留，并记录会话当前最新 `seq`。群 inbox 保留。
6. **未读 = `last_seq - read_seq`。** 结果小于 0 按 0。私聊和群聊使用同一个公式。发送者的水位仍然异步推进，所以私聊刚发完的几十毫秒内，会话列表可能把自己的消息算成未读，下一次 `focus` 恢复；群聊本来就是这样。群的已读人数仍然是对成员水位做 `ZCOUNT`，不变。
7. **水位线的单位换成 `seq`。** Redis 里的私聊水位值、群水位的分数，以及 MySQL 的已读位置都改用 `seq`。
8. **持久化与故障前提沿用 v1.8 总览。** AOF 保持 `everysec`；启动和 Redis 重启后先校准计数器再接纳；客户端按编号对账。
9. **群 inbox 的分数改为 `seq`。** 成员仍是全局消息号。按编号翻页，以及按（群，`seq`）定位消息发送者，都是一次范围查询。
10. **游标和参数直接换成 `seq`，不保留旧参数。** 单会话历史（私聊、群聊）的 `before_id`、`after_id` 改为 `before_seq`、`after_seq`；bootstrap 里每个群的游标改为 `after_seq`；`read-stats` 的 `message_id` 改为 `seq`；`focus.ack`、`messages.read` 等里的 `last_read_message_id` 改名为 `last_read_seq`。私聊的 feed 增量同步仍用全局消息号 `after_id`。
11. **不做向后兼容。** 当前正式实例只有开发者本人使用，所有用户在 v1.x 全部开发完成后才开始使用，所以接口和字段直接替换，没有刷新的旧页面不再保证可用。旧的 HTTP 已读接口（`POST /api/read`、`POST /api/conversations/:username/read`、`POST /api/groups/:id/read`）原本为兼容和回滚保留，随之删除；回滚靠备份和旧发布包。
12. **MySQL 用生成列实现私聊会话唯一约束。** `messages` 增加由 `LEAST(sender_id, recipient_id)` 和 `GREATEST(sender_id, recipient_id)` 生成的两列，加（小 ID、大 ID、`seq`）唯一索引，不新建会话表。群消息用（`group_id`、`seq`）唯一索引。
13. **保留无 Redis 的本地开发路径。** 在 MySQL 事务里用 `MAX(seq)+1` 分配，只限本地开发，不用于生产。
14. **发现 Redis 重启。** 后端每 5 秒读一次 Redis 的 `run_id`，变化即触发计数器校准；任何 Redis 连接错误也立即触发一次检查，缩小检测前的空窗。校准期间接纳返回 503。
15. **掉电丢尾后允许原客户端 ID 重发。** 客户端对账发现本地“已发送”的消息在服务端不存在时，标记为发送失败，沿用现有的失败重试入口，重发时使用原客户端 ID。

## 数据模型

键名为草案，实现时可以调整。

### Redis

| 键 | 类型 | 内容 |
| --- | --- | --- |
| `dm:seq:{小ID}:{大ID}` | STRING | 私聊会话计数器，当前最大 `seq` |
| `dm:pair:{小ID}:{大ID}` | ZSET | 私聊会话索引：成员为全局消息号，分数为 `seq` |
| `group:{G}:seq` | STRING | 群会话计数器 |
| `dm:conv-last:{user}` | HASH | 保留：对方 → 最新消息，并带上该会话最新 `seq` |
| `dm:read:{user}` | HASH | 保留：对方 → 已读 `seq`（单位变化） |
| `group:{G}:read` | ZSET | 保留：成员 → 已读 `seq`（单位变化） |
| `group:{G}:inbox` | ZSET | 保留；成员为全局消息号，分数改为 `seq` |
| `seq:ready` | STRING | 历史回填和编号完成的标记 |

- 废弃 `dm:conv:{owner}:{peer}`。
- 幂等记录（`dedup`、`group-dedup`）增加 `seq` 字段，重复发送时返回。
- 消息实体（`messages:{id}`、`group-messages:{id}`）增加 `seq` 字段。
- 所有新键不设 TTL，容量治理留到 v1.9。

### MySQL

- `messages` 和 `group_messages` 新增会话消息号列，并加（会话，`seq`）唯一约束。私聊的会话由发送者与接收者的小 ID、大 ID 确定。
- `conversation_reads` 和 `group_members` 新增 `last_read_seq` 列，旧的 `last_read_message_id` 保留，便于回滚。
- 异步落库带着 `seq`。同一（会话，`seq`）对应不同消息时按冲突处理，记录日志，不静默覆盖。

## 计数器的初始化与恢复

- **回填。** 给所有已有会话设置计数器，值取回填后该会话的最大 `seq`，然后写入 `seq:ready`。
- **运行期缺失。** `seq:ready` 存在时，会话计数器不存在表示这是新会话，从 1 开始。
- **Redis 数据全丢。** `seq:ready` 同时丢失，接纳返回 503，直到重新回填。与 v1.6、v1.7 的门禁一致。
- **只丢 AOF 尾部。** `seq:ready` 还在，但计数器可能落后于 MySQL：消息经 RabbitMQ 落库只要几毫秒，早于 1 秒一次的 fsync。因此后端启动时，以及发现 Redis 重启后，先把每个会话的计数器抬到不低于 MySQL 里该会话的最大 `seq`，只抬不降。校准完成之前接纳返回 503。
- **发现 Redis 重启（草案）。** 后端定期读取 Redis 的 `run_id`，变化即触发校准。
- **全局消息号。** 沿用现有 `seed_floor` 机制，不变。

## 读状态

- `dm:read`、`group:{G}:read` 的值换成 `seq`。推进规则不变：只增不减，Lua 内比较后写入，推进时写 Stream。
- 推进的候选位置不再需要查消息索引，取 `min(请求的 through, 会话最新 seq)`。
- 会话列表和 bootstrap：私聊未读 = 会话 `last_seq`（来自 `dm:conv-last`）减去 `dm:read`；群聊未读 = 群计数器减去 `group:{G}:read` 里自己的分数。都用 pipeline 批量读取。
- 对方的已读回执：对方的水位大于等于我最后一条消息的 `seq`。
- 群已读人数：对成员水位做 `ZCOUNT`，阈值换成该消息的 `seq`，其余规则与 v1.7 相同。
- MySQL 异步持久化：`last_read_seq` 用 `GREATEST` 写入，机制与 v1.6、v1.7 相同。
- 入群基线：取群计数器的当前值，不再取 `max(MySQL 最新消息号, last_accepted_id)`。计数器经过校准，不会低于 MySQL。
- 启动重建群水位：从 MySQL 的 `last_read_seq` 补齐缺失成员、抬高偏低的位置，只增不降，规则与 v1.7 相同。
- `focus` 立即推进到会话最新 `seq`。

## 接口

- 消息体、WebSocket 推送、同步响应增加 `seq`；会话列表增加 `last_seq`。
- 全局消息号 `id` 保留，私聊 feed 增量同步和 `after_id` 游标不变。
- 单会话历史的 `before_id`、`after_id` 改为 `before_seq`、`after_seq`；bootstrap 的群游标改为 `after_seq`，服务端用会话 `last_seq` 与它直接比较。
- `read-stats` 的 `message_id` 改为 `seq`；`focus.ack`、`messages.read` 等里的 `last_read_message_id` 改名为 `last_read_seq`。
- 删除旧的 HTTP 已读接口，已读只走 WebSocket `focus`。
- 不保留旧参数和旧字段。

## 客户端

收到某会话编号为 N 的消息，本地该会话最大编号为 M：

- N = M + 1：追加；
- N > M + 1：存在缺口，按缺失区间向服务端补拉；
- N <= M 且全局消息号相同：重复，忽略；
- N <= M 且全局消息号不同：服务端回退后编号被重用，以服务端为准，重新同步该会话的尾部；
- 会话列表里的 `last_seq` 小于本地最大编号：服务端回退过，丢弃多出来的本地尾部并重新同步；
- 补拉后仍取不到的编号，标记为缺失，不无限重试；
- 本地“已发送”的消息在对账中发现服务端不存在（掉电丢尾）：标记为发送失败，保留原客户端 ID，用户点击重试时用原客户端 ID 重发。丢尾时服务端的去重记录和消息一起丢失，重发会当作新消息接纳，不会重复。

IndexedDB 缓存增加 `seq` 字段，需要升级缓存版本。服务端仍是权威，沿用 v1.5 的原则。

## 历史回填与切换

一次性命令，幂等，停后端后执行，顺序与 v1.7 相同：备份 → 停后端 → 替换文件 → 回填 → 启动。

1. 按会话分组，按全局消息号顺序给所有历史私聊和群消息编号，写入 MySQL 新增列；
2. 在 Redis 里建立 `dm:pair`，设置会话计数器和消息实体上的 `seq`；
3. 把已有已读位置从全局消息号换算成 `seq`，写入 Redis 和 MySQL 新增列。换算规则：取该会话内全局消息号不大于该位置的最后一条消息的 `seq`，没有则为 0；
4. 校验：每个会话的消息条数等于最大 `seq`，每个已读位置不小于换算值；
5. 通过后写入 `seq:ready`。

回滚方案（草案）：旧列和群 inbox 保留，回滚到 v1.7 时需要先用 `backfill-read` 重建已被废弃的 `dm:conv`。

## 失败与降级

| 场景 | 行为 |
| --- | --- |
| Redis 不可用 | 接纳、已读、未读相关接口失败，不回落 MySQL，与 v1.6、v1.7 一致 |
| MySQL 不可用 | 编号分配、未读、已读照常，异步落库积压重试 |
| 计数器落后于 MySQL（丢 AOF 尾部） | 启动或发现 Redis 重启后校准，校准完成前接纳返回 503 |
| `seq:ready` 丢失 | 接纳和读状态返回 503，重新回填后恢复 |
| 落库遇到（会话，`seq`）冲突 | 记录日志，不覆盖；客户端按对账规则恢复 |
| 掉电丢 AOF 尾部（约 1 秒内） | 已确认的消息可能丢失；客户端发现本地多出的尾部后，以服务端为准重新同步，自己发的消息标记为发送失败，可用原客户端 ID 重发 |

## 实现中确定的细节

这些不需要产品决策，实现时按下面的原则处理，结果记入实现进展。

1. **热读边界。** 会话索引改为按 `seq` 排序后，原来按全局消息号设置的 `index:epoch` 过滤不能再直接用作分数下界。原则不变：索引里有、但消息实体缺失的老消息（回填只写了编号）视为不完整，回落 MySQL，沿用现有的 `missing` 判断。
2. **校准的执行方式。** 启动时按批读取 MySQL 里每个会话的最大 `seq` 并抬高计数器，会话数很多时要控制批大小和启动耗时；Redis 重启后的校准复用同一段逻辑。
3. **MySQL 回填编号。** 现有历史消息按会话分批编号，避免长事务和锁表。
4. **删除旧 HTTP 已读接口的影响面。** 相关的 Go 测试、smoke 用例和前端残留引用要同步清理。
5. **bootstrap 的群增量。** 群游标改为 `after_seq` 后，服务端用会话 `last_seq` 比较，不再依赖群最后一条消息的全局号。

## 实施小步（草案）

开始实现前再细化。

1. **MySQL 迁移与 store：** 新增列和唯一约束，落库带 `seq`，回填所需查询。
2. **Redis 计数器与接纳 Lua：** 私聊、群聊分配 `seq`，幂等返回原编号，消息实体和会话索引带 `seq`，建立 `dm:pair`。
3. **读路径：** 历史、feed、bootstrap、sync 返回 `seq`，用 `dm:pair` 替代 `dm:conv`。
4. **读状态：** 水位线换成 `seq`，未读公式，`read-stats`，异步持久化，删除旧的 HTTP 已读接口。
5. **回填、校准与门禁：** 回填命令，`seq:ready`，启动和 Redis 重启后的校准。
6. **接口与前端：** `seq` 字段，缺口检测，缓存版本升级。
7. **验证：** 后端 `go test`、`go vet`、`-race`，前端 typecheck、build、Vitest，smoke 增加丢尾、Redis 重启和缺口场景。
8. **隔离验证与正式切换：** 部署到 8199 验证，通过后备份并切换正式 8198，更新运行文档和路线图。

## 验收方向（草案）

1. 每个会话的 `seq` 从 1 开始连续，发送 N 条后最大 `seq` 为 N；重复发送返回同一个 `seq`。
2. 同一会话并发发送，`seq` 无重复、无空洞。
3. 私聊两个方向的消息在同一个会话里按 `seq` 排序；删除好友再加回来后继续编号。
4. 会话列表的私聊和群聊未读逐项正确，且与切换前一致。
5. 异步落库窗口内，未读和已读仍然正确，落库后不变化。
6. 模拟丢一条推送：客户端收到跳号后自动补拉，界面不缺消息。
7. 模拟服务端回退（计数器变小）：客户端发现后以服务端为准重新同步。
8. 重启 Redis（包括丢 AOF 尾部）后，计数器被校准，新消息不撞号；校准完成前接纳返回 503。
9. 回填后每个会话的消息条数等于最大 `seq`，已读位置换算正确；缺少 `seq:ready` 时后端拒绝启动。
10. v1.7 行为不变：隐式已读、群回执、私聊回执、成员管理。
11. 掉电丢尾后，客户端把本地多出的已发送消息标记为发送失败，点击重试用原客户端 ID 重发成功，且不重复。

## 不在本版范围

- 跨实例广播和单会话替换（后续子版本）；
- 可靠投递、pending 接管、死信和对账程序（后续子版本）；
- TTL 和容量治理（v1.9）；
- 消息实体改按（会话，`seq`）存键、彻底去掉会话索引：等 v1.9 有内存实测数据再决定。

## 风险

1. **改动面大。** 涉及消息模型、读模型、接口、前端缓存和回填切换，需要分步实现和完整回归。
2. **已读位置换算。** 回填时把全局消息号换算成 `seq`，换算错误会让未读数偏差，必须校验。
3. **掉电丢尾窗口仍然存在。** 靠校准和客户端对账缓解，不能消除，见 v1.8 总览。
4. **私聊未读短暂偏大。** 发送者水位异步推进期间，自己的消息可能被算成未读。
5. **回滚成本。** 废弃 `dm:conv` 后，回滚到 v1.7 需要先重建它。
6. **新键没有 TTL。** 计数器和会话索引随会话数增长，容量治理留到 v1.9。
