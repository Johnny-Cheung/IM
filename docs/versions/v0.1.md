# v0.1 基础工程

状态：讨论中，尚未实现。

## 目标

建立浏览器端 IM 的前后端基础工程，让本地和开发机都能够运行一个最小可验证版本：浏览器打开基础状态页，页面能够请求后端并展示服务状态。

本版本只搭建工程和验证链路，不开始用户、好友、消息或其他业务功能。

## 已确认事项

### 产品形态

- 只提供 Web 应用，用户通过浏览器访问。
- 不制作可下载安装的桌面客户端或移动客户端。
- 桌面和手机支持指桌面浏览器、手机浏览器中的网页访问；本版本先保证基础页面可响应式打开。

### 模块结构

- `backend/`：后端服务。
- `frontend/`：浏览器前端。
- 根目录：跨模块配置、文档和部署编排。
- 后端和前端保持独立的启动命令与模块配置。

### 技术栈

- 后端：Go + Gin。
- 前端：React + TypeScript + Vite。

### 后端基础接口

- 提供 `GET /health`。
- 健康接口返回服务存活状态和简单服务标识。
- 本版本不接入 MySQL、Redis、RabbitMQ 等业务基础设施。

### 前端基础页面

- 浏览器打开后展示基础状态页。
- 页面展示 IM 名称、前端加载状态、后端连接状态和服务地址。
- 后端不可用时展示明确的连接错误。

### 启动与运行

- 本地开发时，后端和前端使用两个命令分别启动。
- 根目录提供启动说明，后续可以提供快捷命令，但不把跨平台的一键进程管理作为本版本前提。
- 本地和开发机都要完成验证。
- 开发机运行构建产物：后端编译为 Linux 二进制，前端构建为静态文件。
- 开发机使用独立的 v0.1 运行目录、端口和进程，不接入旧 IM 的数据、配置或进程。
- 开发机具体目录、端口和进程管理方式在部署前根据实际环境确认。

## 本版本不做

- 用户注册、登录和个人资料。
- 好友关系。
- WebSocket 和聊天消息。
- MySQL、Redis、RabbitMQ 等业务基础设施。
- 生产级部署、高可用、压测和性能优化。
- 桌面或移动端可下载安装客户端。

## 实现与部署时细化

- 具体工具版本和最低运行环境。
- `/health` 的响应字段与请求失败提示。
- 前端开发服务器访问后端的配置方式。
- 开发机前端静态产物的托管方式。
- 开发机独立运行时的端口、目录和停止方式。

## 验收方向

本版本实现后，至少需要能够：

1. 在本地分别启动后端和前端。
2. 在本地浏览器打开基础状态页，并看到后端健康状态。
3. 停止后端后，前端显示明确的连接失败状态；后端恢复后页面能够重新检查。
4. 构建 Linux 后端和前端静态产物。
5. 在开发机独立目录运行构建产物，并从浏览器访问基础状态页。
6. 验证开发机运行不影响旧 IM 服务和数据。

具体接口、目录、启动脚本和测试方案在开始实现时继续讨论并记录。
