# v0.1 基础工程

状态：实现中，本地验证通过，开发机独立部署验收待执行。

## 目标

建立浏览器端 IM 的前后端基础工程，让本地和开发机都能够运行一个最小可验证版本：浏览器打开基础状态页，页面能够请求后端并展示服务状态。

本版本只搭建工程和验证链路，不开始用户、好友、消息或其他业务功能。

## 已确认事项

### 产品形态

- 只提供 Web 应用，用户通过浏览器访问。
- 不制作可下载安装的桌面客户端或移动客户端。
- 桌面和手机支持指桌面浏览器、手机浏览器中的网页访问；本版本先保证基础页面可响应式打开。

### 模块结构

- `backend/`：后端服务。
- `frontend/`：浏览器前端。
- 根目录：跨模块配置、文档和部署编排。
- 后端和前端保持独立的启动命令与模块配置。

### 技术栈

- 后端：Go + Gin。
- 前端：React + TypeScript + Vite。

### 后端基础接口

- 提供 `GET /health`。
- 健康接口返回服务存活状态和简单服务标识。
- 本版本不接入 MySQL、Redis、RabbitMQ 等业务基础设施。

### 前端基础页面

- 浏览器打开后展示基础状态页。
- 页面展示 IM 名称、前端加载状态、后端连接状态和服务地址。
- 后端不可用时展示明确的连接错误。

### 启动与运行

- 本地开发时，后端和前端使用两个命令分别启动。
- 根目录提供启动说明，后续可以提供快捷命令，但不把跨平台的一键进程管理作为本版本前提。
- 本地和开发机都要完成验证。
- 开发机运行构建产物：后端编译为 Linux 二进制，前端构建为静态文件。
- 开发机使用独立的 v0.1 运行目录、端口和进程，不接入旧 IM 的数据、配置或进程。
- 开发机具体目录、端口和进程管理方式在部署前根据实际环境确认。

## 本版本不做

- 用户注册、登录和个人资料。
- 好友关系。
- WebSocket 和聊天消息。
- MySQL、Redis、RabbitMQ 等业务基础设施。
- 生产级部署、高可用、压测和性能优化。
- 桌面或移动端可下载安装客户端。

## 已确定的实现方式

- 后端使用 Go 1.26 模块和 Gin 1.9.1；前端使用 React 19、TypeScript 5.7+、Vite 8。
- 后端默认监听 `127.0.0.1:8080`，可通过 `-addr` 覆盖。
- `GET /health` 返回 HTTP 200 和 `{"status":"ok","service":"im-backend"}`，不检查外部依赖。
- Vite 默认运行在 `5173`，将相对路径 `/health` 代理到 `http://127.0.0.1:8080`。
- 前端状态页展示 IM 名称、前端已加载、后端连接状态、健康检查地址和后端服务标识；支持手动重新检查，超时为 5 秒。
- 后端通过 `-web-dir` 读取前端构建目录，启动时要求目录中存在 `index.html`，再由 Go 统一提供页面和静态资源。
- v0.1 不实现前端路由 fallback；未知静态资源返回 404。
- 前端使用原生 CSS，不引入状态管理、路由、UI 框架或测试框架。

## 待完成的部署细化

- 开发机独立运行目录、端口、绑定地址和进程管理方式，部署前根据机器状态确认。

## 本地验证记录

已完成：

1. `backend` 和 `frontend` 可分别启动。
2. `GET /health` 返回 HTTP 200 和约定 JSON。
3. Vite 开发代理可从前端访问 `/health`。
4. 前端生产构建通过，Go 直接托管 `frontend/dist` 时首页、静态资源和 `/health` 均可访问。
5. 后端 `go test ./...`、`go vet ./...` 通过；前端 `npm run typecheck`、`npm run build` 通过。
6. 浏览器回归已覆盖后端不可用时的“连接失败”状态，以及后端恢复后的“已连接”状态。
7. `CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build` 通过，产物为静态 Linux amd64 ELF。
