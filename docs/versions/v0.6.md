# v0.6 基础群聊

状态：部署验证通过，等待验收。

## 目标

在私聊基础上加入基础群聊：只能邀请自己的好友入群，群聊与私聊共用会话列表，支持群消息收发、历史分页、未读数量和基础群管理。

## 已确认范围

### 建群与成员

- 任何登录用户都可以建群，创建者成为群主。
- 建群必须填写群名，并至少选择 1 位自己的好友；群名 1–30 个字符，允许重名。
- 群成员上限 100 人（包含群主）。
- 只有两种群身份：群主和普通成员。
- 所有群成员都可以邀请自己的好友入群；被邀请人不需要确认，直接成为成员。
- 被邀请人必须是邀请人的好友；好友关系只影响邀请，不影响已经成为成员的人，之后双方删除好友也不会退出群。
- 已经加入的成员再次被邀请时忽略；被踢出或主动退群的人可以再次被邀请。
- 普通成员可以主动退群；群主可以踢出任意普通成员，但不能踢自己。
- 只有群主可以解散群；群主退群即自动解散群，前端必须二次确认。
- 群主可以修改群名，不支持转让群主。

### 群消息与历史

- 所有成员都能查看群的全部历史，包括自己入群前的消息。
- 新成员入群时，当前已有的群消息视为已读；未读数从入群后的新消息开始计算。
- 群消息沿用私聊规则：纯文本、支持换行和表情，去除首尾空白后 1–2000 个字符。
- 使用 HTTP 发送，服务端保存成功后视为已发送；WebSocket 向群成员实时推送。
- 使用 `client_message_id` 幂等，同一发送者在同一群内重复提交同一条消息只保存一条。
- 群消息按 ID 正序展示，历史默认每页 30 条，滚动到顶部附近加载更早消息。
- 断线重连后，当前打开的群会话通过 `after_id` 补收遗漏消息，规则与私聊一致，单次最多补收 500 条。

### 未读

- 会话列表展示每个群的未读消息数量，只统计其他成员发送且当前用户尚未读到的消息。
- 打开群会话，或当前群会话在前台停留时，自动标记已读；页面在后台时不自动已读，回到前台后再标记。
- 群未读数保存在服务端，刷新、重新登录或换设备后保持。
- 群聊只做未读数量，不做“已读/未读”回执，也不在群消息下展示已读状态。

### 会话列表与群管理

- 群聊和私聊混在同一个会话列表，按最后一条消息时间倒序排列。
- 没有消息的会话排在后面；私聊按昵称、用户名排序，群聊按创建时间倒序排列。
- 会话项显示群名、最后一条消息和未读数；群消息预览可以带上发送者昵称。
- 群会话头部显示群名和成员数量，提供“群信息”入口。
- 群信息面板展示群名、群主和成员列表；群主可以改群名、邀请、踢人和解散；普通成员可以邀请和退群。
- 群聊和私聊共用 `/chat` 工作区；群聊路由使用 `/chat/group/{groupId}`，刷新后恢复。
- 被踢出、群被解散后，群从会话列表移除，当前正在查看时返回会话列表并提示。

### 实时事件

- 群消息通过现有单聊天 WebSocket 推送，群成员在线时实时收到。
- 成员变化、群名修改、被踢出和解散通过 `group.changed` 事件通知相关用户，前端刷新会话列表和群信息。
- 不新增群已读回执事件。

## 数据模型

新增 3 张表，迁移编号从 `011` 开始。群表使用 `chat_groups`，避免与 MySQL 的 `GROUPS` 关键字冲突。

### `chat_groups`

- `id`：自增主键，群 ID。
- `name`：群名，1–30 个字符。
- `owner_id`：群主，关联 `users.id`。
- `created_at`：创建时间，UTC。
- `dissolved_at`：解散时间；为 `NULL` 表示正常群。解散后保留数据，但所有接口和会话列表都不再返回该群。

### `group_members`

- `group_id`、`user_id`：联合主键，关联群和用户。
- `joined_at`：入群时间。
- `last_read_message_id`：该成员最后读到的群消息 ID；入群时设为当前群最新消息 ID，历史视为已读。
- 退群或被踢时删除成员行；重新入群时重新建立，并重新以当前最新消息为已读起点。

### `group_messages`

- `id`：自增主键，同时作为历史分页和未读计算游标。
- `group_id`：所属群。
- `sender_id`：发送者。
- `client_message_id`：客户端幂等 ID。
- `body`：正文，最多 2000 个字符。
- `created_at`：服务端接收时间，UTC。
- 唯一键 `(group_id, sender_id, client_message_id)`；索引支持按群分页和查询最后一条消息。

## 接口

所有接口都需要登录，错误格式沿用 `{"error":{"code":"...","message":"..."}}`。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/conversations` | 返回私聊和群聊的统一会话列表 |
| `POST` | `/api/groups` | 建群，创建者为群主 |
| `GET` | `/api/groups/{id}` | 群信息和成员列表，仅成员可见 |
| `PATCH` | `/api/groups/{id}` | 群主修改群名 |
| `POST` | `/api/groups/{id}/members` | 邀请自己的好友入群 |
| `DELETE` | `/api/groups/{id}/members/{username}` | 群主踢人 |
| `POST` | `/api/groups/{id}/leave` | 退群；群主调用时解散群 |
| `GET` | `/api/groups/{id}/messages` | 群历史，支持 `before_id` / `after_id` 和 `limit` |
| `POST` | `/api/groups/{id}/messages` | 发送群消息 |
| `POST` | `/api/groups/{id}/read` | 标记群消息已读 |

### 统一会话列表

私聊项保留原有字段并增加 `type`：

```json
{
  "type": "direct",
  "user": {"username": "alice", "nickname": "Alice"},
  "is_friend": true,
  "last_message": {},
  "unread_count": 0,
  "peer_last_read_message_id": 12
}
```

群聊项：

```json
{
  "type": "group",
  "group": {
    "id": 1,
    "name": "项目群",
    "owner": "johnny",
    "member_count": 5
  },
  "is_owner": true,
  "last_message": {},
  "unread_count": 3
}
```

群消息对象包含 `id`、`group_id`、`sender`、`body`、`client_message_id`、`created_at`。

### 建群与邀请

- 建群请求：`{"name": "项目群", "member_usernames": ["alice"]}`。
- 邀请请求：`{"usernames": ["bob"]}`。
- 用户名去重后处理；建群时群主以外的成员至少 1 人。
- 邀请和建群都是全成或全不成：任一用户不存在、不是邀请人的好友或超出人数上限时，整个请求失败。

### 主要错误码

- `group_not_found`：群不存在、已解散或当前用户不是成员。
- `not_owner`：不是群主。
- `not_friends`：被邀请人不是邀请人的好友。
- `group_full`：群成员已达到 100 人。
- `invalid_group_name`：群名为空或超过 30 个字符。
- `invalid_members`：成员列表为空、包含自己或格式不正确。
- `member_not_found`：被踢用户不在群里。
- `cannot_kick_self`：群主不能踢自己。
- `invalid_message`、`message_too_long`、`invalid_client_message_id`：沿用私聊规则。

## WebSocket 事件

- `group.message.created`：群消息保存成功后推送，包含完整群消息对象。
- `group.changed`：成员变化或群状态变化，包含 `group_id` 和 `action`：
  - `added`：新成员入群，推送给新成员。
  - `members_changed`：成员列表变化，推送给其余成员。
  - `removed`：被踢出，推送给被踢成员。
  - `renamed`：群名修改，推送给所有成员。
  - `dissolved`：群解散，推送给所有成员。
- 事件只用于让前端刷新会话列表和群信息；消息和成员数据仍以 HTTP 接口为准。

## 前端行为

- 会话列表增加“发起群聊”入口：填写群名、勾选好友后创建。
- 群会话项显示群名、最后一条消息和未读数；群消息预览带发送者昵称。
- 群聊天页头部显示群名和成员数量，点击“群信息”打开面板。
- 群信息面板展示成员列表和群主标识；按权限显示邀请、改群名、踢人、退群或解散。
- 群消息中，其他成员的消息显示发送者昵称；自己发送的消息保持右对齐。
- 群聊不显示“已读/未读”回执。
- 收到 `group.changed` 时刷新会话列表；当前群被踢出或解散时返回会话列表并提示。
- 移动端保持会话列表与对话切换；群信息、建群对话框在窄屏下可正常操作。

## 本版本不做

- 群邀请确认流程、邀请链接和群二维码。
- 群主转让、管理员、群公告、群头像和群昵称。
- 加入/退出/踢出/改名的系统消息。
- 群消息已读回执、已读人数和已读列表。
- @提醒、消息免打扰、置顶、群搜索和成员搜索。
- 图片、文件、语音、视频和消息撤回。
- 群主或成员对好友关系之外的用户直接拉群。
- 解散后保留群历史入口；解散、被踢或退群后不能继续访问历史。

## 验收方向

1. 任意用户填写群名并选择至少 1 位好友建群，创建者成为群主，成员在会话列表看到新群。
2. 群成员邀请自己的好友直接入群；邀请非好友、重复成员或超过 100 人时按规则处理。
3. 群内消息实时收发，发送方和在线成员都能收到；重复 `client_message_id` 不产生重复消息。
4. 群历史可按页加载，所有成员都能看到入群前的历史；新成员入群时历史不产生未读。
5. 群未读数在打开会话、前台停留、后台页面、刷新和重连后正确。
6. 普通成员可退群；群主可踢人；被踢或退群后群从列表消失且无法再读取历史；被踢者可以再次被邀请。
7. 群主可改群名和解散；群主退群时二次确认并自动解散，所有成员的会话列表移除该群。
8. 群聊和私聊按最后消息时间统一排序，空会话排在后面；刷新 `/chat/group/{id}` 后恢复当前群。
9. 桌面和手机布局正常，无横向溢出；原有私聊、好友和未读功能回归通过。
