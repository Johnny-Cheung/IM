# v1.1 性能基线与基础设施准备

状态：准备完成（2026-10-25），未接入业务，待验收。

## 目标

在不改变 v0.7 业务逻辑的前提下，建立可重复的 API 性能基线，并把 Redis、RabbitMQ 和可选的后端连接能力准备好，供 v1.2 起使用。

## 已完成

### 性能基线

- 新增 `scripts/perf-baseline.mjs`，只调用现有公开 API。
- 覆盖私聊发送、群聊发送、会话列表、私聊历史、群聊历史、私聊已读和群聊已读。
- 固定 3 个隔离账号、固定历史数据和 `limit=30`；3 轮预热后串行采样 20 轮，不使用并发或压力测试。
- 输出 p50/p95/max 到报告目录的 `perf-baseline.json`；不设置性能阈值。

2026-10-25 在 `8199` 隔离环境的一次结果（客户端完整 HTTP 往返）：

| 场景 | p50 | p95 |
| --- | --- | --- |
| 私聊发送 | 59.1 ms | 71.2 ms |
| 群聊发送 | 54.3 ms | 61.1 ms |
| 会话列表 | 58.1 ms | 111.1 ms |
| 私聊历史 | 54.4 ms | 63.1 ms |
| 群聊历史 | 56.9 ms | 74.4 ms |
| 私聊已读 | 52.4 ms | 69.2 ms |
| 群聊已读 | 51.4 ms | 71.8 ms |

### 后端可选基础设施能力

- 新增 `backend/internal/config/infra.go`：Redis/RabbitMQ 配置为空时完全关闭，不连接默认地址。
- 新增 `backend/internal/infra/`：连接、探针、基础退避重连和并发安全状态快照；不导入 `store` 或 `httpapi`。
- 新增 `GET /ops/infra`，仅在至少启用一个组件时注册；不改变 `/health` 和 `/ready`，业务接口和数据库结构未变。
- 新增 `backend/cmd/infra-check/main.go`，独立验证 Redis SET/GET/DEL 和 RabbitMQ 发布/消费/确认。
- 未配置基础设施时，后端启动、API 和健康检查与 v0.7 一致；基础设施不可用不阻塞 HTTP 启动。

### 开发机基础设施

- 使用独立目录 `/opt/IM-Rebuild/infra-v11`、独立私有 Docker runtime 和独立凭据，不影响 v0.7 runtime、MySQL、8198 或旧 `/opt/IM`。
- Redis `7.2-alpine`：`127.0.0.1:26379`，96 MiB，启用密码和 AOF。
- RabbitMQ `3.13.7`：`127.0.0.1:25676`，512 MiB，独立 vhost/user；Prometheus 探针改到 `25677`，避免与旧服务冲突。
- 离线镜像来自既有 `/opt/IM/images` 的复制件，开发机未使用外部镜像仓库。
- 管理入口：`/opt/IM-Rebuild/infra-v11/infractl`，提供 `start/stop/restart/status/health/logs` 和单组件重启。

## 验证结果

- `infra-check`：Redis 读写、RabbitMQ 发布/消费/确认通过。
- 停止 Redis 和 RabbitMQ 时，`/ready` 均保持 200；恢复后状态回到 connected，重连计数增加。
- 现有 API 回归 56 项、浏览器回归 37 项通过；性能基线脚本 7 项功能检查通过。
- 验证结束后已停止 `8200` 验证实例、恢复 canary `8199` 到 v0.7 二进制；本轮测试账号按 manifest 精确清理 17 个，并清理此前遗留的 101 个容量测试账号。
- 正式 `8198` 未更新、未重启，`/health`、`/ready` 正常；`imctl verify-host` 显示宿主机基线未变。

## 本版没有做

- 没有把私聊、群聊或已读切换到 Redis/RabbitMQ。
- 没有新增消息格式、邮箱、游标拉取、业务表或用户可见行为。
- 没有开启基础设施的正式服务配置，没有多实例、高可用或公网部署。
- 没有做压力测试、容量调优或性能阈值判定；这些留到后续版本。

## 当前限制

- Redis/RabbitMQ 是独立准备环境，当前仅供基础设施验证；正式后端未启用。
- 独立 Docker runtime 与 v0.7 相同，不配置开机自启，开发机重启后需手动执行 `infractl start`。
- 基础设施密码保存在 `/opt/IM-Rebuild/infra-v11/secrets`（root 可用）；未接入业务前不复制到其他位置。
