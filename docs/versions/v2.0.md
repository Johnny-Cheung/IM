# v2.0 朋友圈（文字版）

状态：开发完成，已通过 8199 隔离验证（2026-10-30）。属于 [v2.x 社交功能](v2.md)，依赖现有的账号、好友关系和 WebSocket 连接。

## 目标

在 IM 里增加一个轻量的朋友圈：

- 发布纯文字动态，支持换行，最多 1000 字；
- 每条动态可选“好友可见”（默认）或“仅自己可见”；
- 浏览自己和好友的动态，按发布时间倒序，分页加载；
- 点赞、取消点赞；
- 单层评论，删除自己的评论；动态作者可以删除自己动态下的评论；
- 删除自己的动态；
- 好友发布新动态时，导航上显示红点；进入朋友圈后清除。

范围只含单体：一个后端进程、一个 MySQL。不引入 Redis 读模型、消息队列或异步落库。

## 不在本版范围

- 图片、视频、语音和任何媒体存储；
- “部分好友可见 / 不给谁看”等隐私名单；
- 评论回复、@、转发、收藏；
- 通知中心、消息列表、未读逐条提醒；
- 全文搜索、推荐、话题；
- 多实例和跨设备实时同步。

## 为什么不用聊天那套链路

朋友圈和聊天消息的读写特征不同：

- 写入频率低，不需要 Redis 先接纳再异步落库；
- 数据是强关系型的（作者、好友、可见性、点赞、评论），事务和唯一约束比异步幂等更直接；
- 分页游标是数据库自增 ID，不需要会话内 `seq`；
- 点赞和评论要求即时一致，数据库事务正好满足。

因此 v2.0 **不新增任何 Redis key、Stream、RabbitMQ 队列或后台 worker**，也不改对账和重建逻辑。

## 数据模型

新增 4 张表，每张表一个迁移文件：

### `moments`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BIGINT UNSIGNED AUTO_INCREMENT | 动态 ID，也是分页游标 |
| `author_id` | BIGINT UNSIGNED | 作者 |
| `body` | TEXT | 纯文本正文，1–1000 字 |
| `visibility` | VARCHAR(16) | `friends` 或 `private` |
| `like_count` | INT UNSIGNED | 冗余计数，事务更新 |
| `comment_count` | INT UNSIGNED | 冗余计数，事务更新 |
| `created_at` | DATETIME(3) | 发布时间 |
| `deleted_at` | DATETIME(3) NULL | 软删除 |

索引：

- 主键 `(id)`，feed 的排序和游标都走主键倒序；
- `(author_id, id)`：按作者取动态，也用于好友 `IN` 查询的候选行。

约束：

- `author_id` 外键到 `users`，`ON DELETE CASCADE`；
- `visibility` 用 `CHECK` 限定取值；
- `body` 非空。

### `moment_likes`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BIGINT UNSIGNED AUTO_INCREMENT | 点赞记录 ID，用于分页 |
| `moment_id` | BIGINT UNSIGNED | 动态 |
| `user_id` | BIGINT UNSIGNED | 点赞者 |
| `created_at` | DATETIME(3) | 点赞时间 |

唯一键 `(moment_id, user_id)` 保证同一人只能赞一次；另建 `(moment_id, id)` 用于点赞列表分页，`(user_id, moment_id)` 便于“我赞过的动态”将来使用。两个外键都 `ON DELETE CASCADE`。

### `moment_comments`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BIGINT UNSIGNED AUTO_INCREMENT | 评论 ID，也是分页游标 |
| `moment_id` | BIGINT UNSIGNED | 所属动态 |
| `author_id` | BIGINT UNSIGNED | 评论者 |
| `body` | VARCHAR(500) | 单层评论正文，1–500 字 |
| `created_at` | DATETIME(3) | 评论时间 |
| `deleted_at` | DATETIME(3) NULL | 软删除 |

索引：主键 `(id)`、`(moment_id, id)`；外键到动态和用户，`ON DELETE CASCADE`。

### `moment_seen`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `user_id` | BIGINT UNSIGNED | 用户 |
| `last_seen_id` | BIGINT UNSIGNED | 已看到的最新动态 ID |
| `updated_at` | DATETIME(3) | 更新时间 |

主键 `(user_id)`，外键到 `users`，`ON DELETE CASCADE`。

### 计数一致性

- 点赞：`INSERT IGNORE`；只有真正插入时在同一事务里 `like_count + 1`。取消点赞只有在确实删除到行时在同一事务里 `like_count = IF(like_count > 0, like_count - 1, 0)`。
- 评论：插入评论和 `comment_count + 1` 同事务；删除评论时先确认行未删除，软删除和 `comment_count = IF(comment_count > 0, comment_count - 1, 0)` 同事务。
- 动态软删除不修改计数；动态不可再访问，计数失去意义。
- 计数冗余避免 feed 的 N+1 查询；v2.0 不做后台对账，靠事务和集成测试保证。

## 可见性与权限

“好友”指 `friendships` 表中存在 `(user_id=查看者, friend_user_id=作者)` 的有向行；建好友时已经双向写入。

| 操作 | 规则 |
| --- | --- |
| 看动态 | 作者本人；或与作者是好友且 `visibility=friends` |
| 看私密动态 | 只有作者 |
| 点赞/取消点赞 | 能看这条动态的人 |
| 评论 | 能看这条动态的人 |
| 删除动态 | 作者 |
| 删除评论 | 评论作者，或该动态的作者 |
| 看点赞列表 | 能看这条动态的人 |
| 看评论列表 | 能看这条动态的人 |

边界行为：

- 删除好友后，双方立即看不到对方新的好友可见动态；已经打开的页面下一次请求返回 404/403。
- 私密动态不进好友 feed，也不广播。
- 动态被删除后，点赞和评论接口返回 `404 moment_not_found`。
- 已删除的评论不出现在列表里，计数同步减少。

## API

所有接口在现有 `/api` 组下，使用现有会话鉴权和错误格式。请求体上限沿用 64KB。

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| `POST` | `/api/moments` | 发布动态 |
| `GET` | `/api/moments?before_id=&limit=` | 好友动态流 |
| `GET` | `/api/moments/:id` | 动态详情 |
| `DELETE` | `/api/moments/:id` | 删除自己的动态 |
| `PUT` | `/api/moments/:id/like` | 点赞（幂等） |
| `DELETE` | `/api/moments/:id/like` | 取消点赞（幂等） |
| `GET` | `/api/moments/:id/likes?before_id=&limit=` | 点赞人列表，按点赞时间倒序 |
| `GET` | `/api/moments/:id/comments?before_id=&limit=` | 评论列表，按评论时间正序返回一页 |
| `POST` | `/api/moments/:id/comments` | 发表评论 |
| `DELETE` | `/api/moments/:id/comments/:commentId` | 删除评论 |
| `GET` | `/api/moments/unread` | 好友新动态红点 |
| `POST` | `/api/moments/seen` | 更新已看到的最新动态 ID |

### 发布动态

请求：

```json
{ "body": "今天天气不错", "visibility": "friends" }
```

- `body` 去首尾空白后 1–1000 字；
- `visibility` 缺省为 `friends`，只接受 `friends`/`private`；
- 返回 `201` 和完整动态对象。

### 动态流

- `before_id` 缺省 0，表示最新一页；`limit` 默认 20、最大 50；
- 只返回未删除、且对当前用户可见的动态；
- 结果按 `id DESC`；
- 每页额外查询这些动态的最新 2 条评论作为预览；
- 返回：

```json
{
  "moments": [
    {
      "id": 12,
      "author": { "username": "demo_alice", "nickname": "Alice" },
      "body": "今天天气不错",
      "visibility": "friends",
      "created_at": "2026-10-30T10:00:00Z",
      "like_count": 3,
      "comment_count": 2,
      "liked_by_me": true,
      "mine": false,
      "comments_preview": [
        { "id": 8, "author": { "username": "demo_bob", "nickname": "Bob" }, "body": "确实" }
      ]
    }
  ],
  "has_more": true,
  "next_before_id": 12
}
```

### 动态详情

返回单条动态、当前用户是否可删除、点赞人前 50 个、最新 100 条评论及 `comments_has_more`。评论页按时间正序展示，更多更早的评论用评论列表接口按 `before_id` 继续拉。

### 点赞与评论

- 点赞幂等：重复点赞返回当前计数，不报错；
- 取消未点赞的动态也返回当前计数；
- 评论返回 `201` 和评论对象；
- 评论列表按 `before_id` 取更早的一页，单页内按时间正序返回；`before_id` 为当前页最早一条评论 ID；
- 删除评论成功返回 `204`。

### 红点

- `GET /api/moments/unread` 返回 `{ "has_new": true, "last_seen_id": 10 }`；
- `POST /api/moments/seen` 请求 `{ "last_seen_id": 12 }`，服务端只向前推进，不后退；
- 只统计“好友 + `visibility=friends` + 未删除 + `id > last_seen_id`”的动态，最多查一条判断是否存在。

### 错误码

| 场景 | 状态 | code |
| --- | --- | --- |
| 正文为空/超长、可见性非法、分页参数非法 | 400 | `invalid_moment_body` / `invalid_visibility` / `invalid_moment_cursor` |
| 非好友、无权查看 | 403 | `not_friend` |
| 不是动态或评论作者 | 403 | `forbidden` |
| 动态/评论不存在或已删除 | 404 | `moment_not_found` / `comment_not_found` |
| MySQL 不可用或查询失败 | 500 | `internal_error` |

## 实时更新

v2.0 只做一个轻量事件：

- 好友发布 `visibility=friends` 的动态后，服务端通过现有 WebSocket hub 向在线好友广播：

```json
{ "type": "moment.created", "moment_id": 12, "author": { "username": "demo_alice", "nickname": "Alice" } }
```

- 客户端收到后只更新导航红点，不自动插入 feed；
- 私密动态不广播；
- 点赞和评论不广播，打开详情或刷新时读取最新计数；
- 事件不持久化；漏掉的事件由 `/api/moments/unread` 在页面加载时补上。

## 前端

- 新增路由 `/moments`，在主导航“好友管理 / 账号设置”旁增加“朋友圈”；
- 页面结构：
  - 顶部发布框：多行文本、可见性选择（好友可见/仅自己可见）、发布按钮；
  - 动态列表：作者昵称、相对时间、正文（保留换行）、点赞/评论按钮、计数、最新 2 条评论预览；
  - 点击动态展开详情：完整评论、评论输入框、点赞人列表、删除入口；
  - “加载更多”按 `before_id` 翻页；
  - 删除动态/评论前二次确认。
- 不做 IndexedDB 缓存，页面打开时从服务端拉取；返回朋友圈页面或刷新时重新拉第一页。
- 导航红点：ChatPage 已有的 WebSocket 连接收到 `moment.created` 后置位；进入 `/moments` 并成功加载第一页后调用 `seen`，清除红点。
- 文本由 React 转义；服务端只存纯文本，不做 HTML。

## 失败与降级

| 场景 | 行为 |
| --- | --- |
| MySQL 不可用 | 动态、点赞、评论返回 500，前端显示错误并允许重试 |
| 重复点赞/取消 | 幂等，返回当前计数 |
| 动态被作者删除 | feed 不再出现；详情、点赞、评论返回 404 |
| 好友关系被删除 | 对方动态不可见；打开中的详情下一次请求失败 |
| WebSocket 断开 | 红点不实时；页面加载时通过 unread 查询补上 |
| 评论/动态正文非法 | 400，不写库 |

## 验收方向

1. 两个好友账号：A 发好友可见动态，B 能看到；非好友 C 看不到；A 发私密动态只有 A 能看到。
2. 点赞、取消点赞幂等，计数正确；重复请求不重复计数。
3. 单层评论按时间正序展示；评论作者和动态作者可以删除评论，其他人不能。
4. 删除自己的动态后，feed、详情、点赞、评论都不可再访问。
5. 动态超过 20 条时分页稳定，`before_id` 不重不漏；新动态出现在第一页。
6. 好友发动态后红点出现；进入朋友圈并加载第一页后红点消失。
7. 删除好友后，对方的好友可见动态立即不可见。
8. 聊天、未读、已读、对账、重建行为不变；API/browser smoke 回归通过。
9. 8199 隔离验证：使用本轮独立测试账号，验证后按 manifest 精确清理。

## 风险

1. **feed 查询的文件排序。** `author_id IN (好友...) ORDER BY id DESC` 可能触发 filesort；先用真实 MySQL 跑 `EXPLAIN`，数据量大时再考虑时间线表或按作者取 top-N 合并。
2. **冗余计数漂移。** 事务内更新并用集成测试覆盖；如果以后出现并发或批量操作，再补对账。
3. **红点查询成本。** 用 `LIMIT 1` 判断存在，不返回精确数量。
4. **无图片会显得单薄。** 这是刻意的范围控制，v2.1 再补媒体。
5. **好友删除的即时性。** 已打开的页面可能短暂显示旧内容，下一次请求即失效；不做主动推送。
6. **没有通知中心。** 点赞和评论只在打开详情时可见；如果以后需要，另开子版本。
7. **删除用户的数据。** 依赖外键级联；动态正文删除后不可恢复。
